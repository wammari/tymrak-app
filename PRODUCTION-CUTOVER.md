## Prepared hosting support

`wrangler.production.jsonc` uses a separate `tymrak-production` Worker, explicit production-only entry point, canonical https://www.tymrak.com and pinned production Supabase reference. Staging cannot be turned into production through dashboard variables. Both runtime keys are required as Secrets. Worker preview URLs and workers.dev are disabled; routes are empty, so this file does not replace DNS or expose a customer domain.

`TYMRAK_RELEASE_READY` defaults to `false`. Production API calls fail closed until the operator deliberately changes it to `true` after the gates below. Static assets can still render if an operator subsequently attaches a route. This flag is an operational hold, not proof that a database backup or migration succeeded. Do not mark the release ready based only on a passing build.

Dry run: `npm run check:cloudflare:production`. Local runtime: `npm run test:cloudflare:production` uses fake keys and explicitly overrides the hold for local testing; it sends no database requests. Neither command deploys. Hosted Builds must explicitly run `npm test && npm run build:cloudflare`; production deploy would need `npx wrangler deploy --config wrangler.production.jsonc` after the reviewed cutover. Do not connect main to unattended deployment.
